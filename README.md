## Setup

Make sure to install the dependencies:

```bash
pnpm install
```

## Development Server

Start the development server on `http://localhost:3000`:

```bash
pnpm dev
```

## Production

Build the application for production:

```bash
pnpm build
```

Locally preview production build:

```bash
pnpm preview
```

## Database (Supabase, local)

Uses the [Supabase CLI](https://supabase.com/docs/guides/local-development/cli/getting-started) with
**Declarative Schemas 2.0**: `supabase/schemas/*.sql` is the source of truth for DDL, and migrations are
generated by diffing them (pg-delta engine).

- Copy `.env.example` to `.env` and paste the values from `pnpm supabase status`.
- Ports are remapped to `553xx` (see `supabase/config.toml`) so this stack can run next to other projects.
- Keep `config.toml` free of deprecated keys — the CLI prints `WARN … will be removed in v4` for them.
  Already applied: `auth.email.enable_signup` → `auth.email.enabled`, `auth.sms.enable_signup` →
  `auth.sms.enabled` (the top-level `auth.enable_signup` is not deprecated). Check with
  `pnpm db:restart 2>&1 | grep -c WARN`.

```bash
pnpm db:start              # boot the local stack (Docker)
pnpm db:reset              # apply migrations + supabase/seed.sql, restart fresh
pnpm db:types              # regenerate app/types/database.types.ts

pnpm schema:sync -f add_notes_table   # preview the migration pg-delta generates (no apply)
pnpm schema:sync -f add_notes_table --apply  # write it, apply it, and seed

pnpm db:stop               # stop the stack
pnpm db:shell              # psql into the local database
```

Data changes (rows, seed data) are never tracked by schema diffs: put them in `supabase/seed.sql`.
For a hosted project, run `pnpm db:link`, replace `supabase/schemas/*.sql` with the output of
`pnpm schema:pull`, then `pnpm db:push`.

## Auth (GitHub OAuth)

Sign-in is GitHub OAuth handled entirely by Supabase Auth; the app never sees a password. The
`@nuxtjs/supabase` module keeps the session in `sb-*` httpOnly cookies, so both the browser and the
Nitro routes (`#supabase/server`) act as the signed-in user and Postgres RLS decides what they can read.

1. Create an OAuth app at <https://github.com/settings/applications/new>:
   - Homepage URL: `http://localhost:3000`
   - Authorization callback URL: `http://127.0.0.1:55321/auth/v1/callback`
     (the local API port from `supabase/config.toml`, **not** the default `54321`)
2. Put the client id/secret in a git-ignored env file: they live in the project-root `.env` here
   (alongside the `NUXT_*` vars), and `supabase/.env` works too - `supabase/config.toml` reads them through
   `env(...)`. Keep them in **one** file: an empty assignment in the other can shadow the real value, and then
   the CLI passes the literal `env(GITHUB_OAUTH_CLIENT_ID)` string to Auth instead of disabling the provider.
   `supabase/.env.example` documents the same two variables if you prefer that location.
3. Restart the stack so Auth picks the provider up, then confirm it:

```bash
pnpm db:restart
curl -s http://127.0.0.1:55321/auth/v1/settings | grep -o '"github":[a-z]*'   # "github":true
```

4. Open `http://localhost:3000/todos`: the module's redirect middleware (`redirectOptions.include`)
   sends you to `/login`, remembers the attempted URL in the `sb-redirect-path` cookie, and
   `/auth/callback` finishes the PKCE exchange before returning you to `/todos`.

Relevant files: `nuxt.config.ts` (`supabase.redirectOptions`), `app/pages/login.vue`,
`app/pages/auth/callback.vue`, `app/components/AuthButton.vue`, `server/api/todos/*`.

`GET /api/todos` returns `401` without a session; with one it only ever sees rows whose `user_id`
matches `auth.uid()` (policies in `supabase/schemas/todos.sql`, `to authenticated`). The seeded rows in
`supabase/seed.sql` belong to the local demo user (`11111111-…`), so a fresh GitHub account starts with
an empty list — add your own todos, or change `user_id` in the seed to your local user id.

On a hosted project the same provider is configured in the dashboard (Authentication → Sign in / up →
GitHub) with the callback `https://<project-ref>.supabase.co/auth/v1/callback`, and the public site URL
plus `additional_redirect_urls` must point at the deployed origin.
